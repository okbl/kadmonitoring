# Обособленный спор — движение по карточке kad.arbitr

Программа отслеживает обособленный спор об оспаривании сделки должника в деле о банкротстве.
Вы указываете дату подачи заявления и ссылку на карточку дела на kad.arbitr.ru. Программа:

- **выделяет из карточки именно этот спор.** В карточке банкротного дела сотни документов, а к
  спору относятся те, у которых в поле «В ответ на» стоит ваше заявление. Сюда же попадают
  документы, отвечающие другим документам спора: документы во исполнение определения об
  оставлении без движения, отзыв на определение о принятии и так далее;
- **определяет стадию спора**: подано, оставлено без движения, принято к производству,
  отложено, приостановлено, возвращено, удовлетворено, отказано, апелляция;
- **говорит, что требуется от финансового управляющего**: со ссылкой на норму и сроком, а если
  загружен текст определения, то и с поручениями суда и сроками из самого текста. Состав
  обязанностей зависит от того, кто подал заявление: оспаривает сам управляющий или кредитор;
- **отмечает новые документы** со времени последнего просмотра.

Выводы программы не заменяют юридическую консультацию. Каждое требование показано вместе с
нормой и исходной фразой определения, чтобы его можно было проверить.

## Как запустить

### Основной вариант. Сайт: GitHub сам проверяет карточки

Откройте **https://okbl.github.io/kadmonitoring/**. Устанавливать ничего не нужно.

1. Нажмите «Новый спор», укажите дату подачи заявления и ссылку на карточку kad.arbitr.
2. Нажмите «Отслеживать на GitHub». Откроется готовая задача (issue), нажмите «Submit new issue».
3. Через 1–3 минуты спор появится в «Моих спорах», а в задаче — первый отчёт: стадия, заседание,
   что требуется от управляющего и в какой срок.

Дальше GitHub сам проверяет карточку: по будням каждые два часа с 7 до 19 по Москве, в
выходные — раз в день. Чтобы проверить сейчас, напишите в задаче комментарий «проверить». О новых
документах в задаче появляется комментарий, и GitHub присылает уведомление на почту и в
приложение. Закройте задачу, чтобы снять спор с отслеживания.

Как это устроено: workflow «Проверка споров» (`.github/workflows/monitor.yml`) запускает
`tools/cloud-check.mjs`. Скрипт открывает карточку в Chrome на сервере GitHub, забирает
хронологию из API картотеки и тексты определений из PDF, разбирает их тем же кодом, что и
страница, и публикует результат на сайте (ветка `gh-pages`, папка `data`).

Репозиторий открытый, поэтому задачи и папка `data` видны всем: список отслеживаемых споров и
их движение. Сами карточки на kad.arbitr тоже общедоступны. Если список нужно скрыть, сделайте
репозиторий приватным. Pages для приватного репозитория требует платного тарифа GitHub.

### Без отслеживания: вставка карточки вручную

Та же страница, открытая с сайта или файлом `dist/index.html`, разбирает и вставленную карточку.
Вставленное никуда не отправляется: разбор идёт в браузере, а файл с диска работает и без
интернета. Сама загрузить карточку по ссылке страница не может: kad.arbitr не разрешает другим
сайтам читать свои страницы.

1. Откройте карточку дела на kad.arbitr.ru, нажмите Ctrl+A, затем Ctrl+C.
2. Вставьте её в поле «Страница карточки», укажите дату подачи и нажмите «Разобрать».

Спор сохраняется в файл кнопкой «Сохранить спор» и открывается кнопкой «Открыть спор». Если
вставить в открытый спор свежую карточку, новые документы будут помечены.

### На своём компьютере: сервер с загрузкой по ссылке

Понадобятся [Node.js](https://nodejs.org) версии 22 или новее и Google Chrome либо Microsoft
Edge. Edge есть в любой Windows.

```
npm install
npm start
```

Откройте http://127.0.0.1:8080, нажмите «Новый спор», введите дату подачи, вставьте ссылку на
карточку и нажмите «Загрузить с kad.arbitr». Сервер откроет карточку в браузере без окна,
заберёт хронологию дела и тексты определений из PDF. Кнопка «Сохранить спор» ставит спор на
отслеживание: он появляется в «Моих спорах», и сервер сам перепроверяет его карточку раз в
12 часов.

Если kad.arbitr попросит пройти проверку «вы не робот», запустите сервер с окном браузера и
пройдите проверку один раз:

```
npm run start:window
```

Cookies хранятся в папке `.kad-profile`, поэтому повторная проверка обычно не нужна.

Сервер принимает подключения только с этого компьютера (127.0.0.1): паролей у него нет. Споры
хранятся в папке `data/` и содержат персональные данные участников дела.

#### Настройки (переменные окружения)

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `8080` | порт страницы |
| `HOST` | `127.0.0.1` | `0.0.0.0` открывает сервер в локальной сети, на ваш риск |
| `KAD_CHECK_HOURS` | `12` | как часто перепроверять споры; `0` — не перепроверять |
| `KAD_BROWSER` | — | путь к chrome.exe или msedge.exe, если браузер не нашёлся сам |
| `KAD_WINDOW` | — | `1` — то же, что `npm run start:window` |
| `KAD_DATA` | `./data` | где хранить споры и кэш текстов определений |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | — | если заданы, о новых документах при плановой проверке придёт сообщение в Telegram |

Если браузер не запускается, укажите путь к нему в `KAD_BROWSER` или выполните
`npx playwright install chromium`.

## Как спор выделяется из карточки

1. **Корневое заявление** ищется по дате подачи: допуск несколько дней, потому что карточка
   показывает дату регистрации судом. Учитываются также тип документа («Заявление о признании
   сделки недействительной») и заявитель. Если заявления в карточке ещё нет, корнем становится
   введённая дата подачи.
2. **Сцепление по «В ответ на».** Документ относится к спору, если его «В ответ на» указывает
   на корень или на документ, уже отнесённый к спору. Для этого совпадают дата и название или
   дата и участник. Если картотека отдаёт ссылку на документ по идентификатору, используется она.
3. **Неоднозначность не скрывается.** Банк может подать в один день два заявления. Если
   «В ответ на» подходит к обоим, связь помечается «вероятной» с объяснением причины. Если ответ
   называет чужой предмет («О включении в реестр…»), документ к спору не относится.
4. **Похожее без связи** попадает в раздел «Возможно относится к спору» и в движение спора не
   включается. Документ можно включить или исключить вручную, а корневое заявление можно выбрать
   в «Проверке разбора». Исправления сохраняются вместе со спором.

## Сроки

Сроки, исчисляемые днями, считаются в рабочих днях со следующего дня после события (ч. 3, 4
ст. 113 АПК РФ). Месячные сроки считаются по ст. 114 АПК РФ. Учтены праздники по ст. 112 ТК РФ
и общее правило переноса. Ежегодные переносы выходных, которые устанавливает Правительство,
программе неизвестны. Поэтому срок, внутрь которого попал праздник, помечен знаком ≈: сверьте
его с производственным календарём.

## Ограничения

- Загрузчик проверен на настоящей карточке с серверов GitHub (`tools/kad-probe.mjs`,
  workflow `kad-probe`). Если картотека изменит устройство страницы или API, разбор может
  сломаться: проба покажет, что изменилось. На время поломки карточку можно вставить вручную,
  разбор у вставки тот же.
- Заявления, с которого начался спор, в хронологии картотеки нет. Спор собирается по ссылкам на
  него: по идентификатору документа и по тексту «В ответ на Заявление (дата) от …».
- Итоговое определение картотека подписывает категорией спора: «О признании сделки должника
  недействительной и (или) применении последствий…». Удовлетворено заявление или отказано,
  видно только из резолютивной части, поэтому текст определения загружается из PDF.
- Срок обжалования показан двумя датами. Первая — десять рабочих дней по ч. 3 ст. 223 АПК РФ.
  Вторая — срок, который считает сама картотека (у неё он бывает месяц). Какой срок применим,
  проверьте по тексту определения.
- Разбор определений работает с PDF, у которых есть текстовый слой. Так выглядят акты
  картотеки. Сканы без текста не читаются.
- Стадия определяется по названию документа. Если в карточке название обрезано до
  «Определение», стадия уточняется по резолютивной части загруженного текста.

## Для разработки

```
npm test          # тесты: разбор, правила, выделение спора, сервер на макете картотеки
npm run build     # собрать dist/index.html
npm run font      # скачать шрифт Onest для сборки (в git не хранится)
npm run pages     # собрать и опубликовать страницу в ветку gh-pages (GitHub Pages)
```

| Файл | Что внутри |
|---|---|
| `src/dates.js` | даты и процессуальные сроки |
| `src/kad.js` | разбор карточки (текст или HTML) в записи |
| `src/rules.js` | тип документа, стадия, требования к управляющему, разбор текста определения |
| `src/dispute.js` | выделение спора по «В ответ на», движение, сроки, сводка |
| `src/app.html`, `src/app.js` | страница |
| `build.mjs` | сборка страницы в один файл |
| `server.mjs` | сервер: API, хранение споров, плановая проверка |
| `server/kad-fetch.mjs` | загрузка карточки и PDF через браузер |
| `server/pdf-text.mjs` | текст из PDF |
| `server/card-text.mjs` | какой текст карточки разбирать: из API или со страницы |
| `tools/cloud-check.mjs` | облачная проверка споров-задач в GitHub Actions |
| `tools/kad-probe.mjs` | проба картотеки: что отдаёт kad.arbitr этому компьютеру |

Модули `src/` работают одинаково в браузере и в Node. Сервер считает сводку для списка споров
тем же кодом, что и страница.
